# 设计方案:中立的 AI 回归测试工具(工作名「明镜 / Evalith」)

- **日期**:2026-05-25
- **状态**:Draft v1(方向已确认,待 spec 评审)
- **作者**:PattyWoods + Claude

---

## 1. 一句话定位

一个**中立、好用、面向"做 AI 的人"的 AI 回归测试工具**:你改了一版 prompt / 模型 / Agent 流程,它一眼告诉你——**这次是变好了还是变坏了**。国产模型与海外模型同为一等公民;**开源本地版引流 + 云端团队版变现**(open-core);**中国起步,产品天生面向全球(双语)**。

## 2. 问题与"为什么是现在"(Why now)

1. **凭感觉开发(vibes-based development)是常态**:绝大多数团队改完 prompt 只跑两三个例子,"看着行"就上线。AI 生成代码导致的线上事故同比 +43%;79% 的企业说用了 Agent,只有 11% 真正跑在生产。
2. **评测与可观测性之间有大缝**:89% 的团队加了"监控",但只有 52% 真正做"评测",大多数 Agent 线上事故就出在这条缝里。
3. **被迫用两个工具**:行业共识是"你几乎一定要同时用一个轻量 CI 框架 + 一个带 UI 的平台",这个割裂本身就是机会。
4. **中立性催化剂**:领头羊 Promptfoo 于 2026-03-09 被 OpenAI 收购。在意"不被某个模型厂绑定"的团队——尤其中国团队——出现了一个突然腾出的信任空位。
5. **本土空位**:国产模型(DeepSeek / Qwen / 豆包 / GLM / MiniMax)已达世界一流,国内 AI 应用/Agent 开发井喷,但**没有一个把国产模型/平台当一等公民的评测工具领头羊**。
6. **已知的具体技术痛点**(差异化抓手):测试集会随流量/模型升级而"过期"(distribution drift);LLM-as-judge 与人工判断常不相关(metric misalignment);把 judge 塞进每个 PR 会让 CI 又慢又贵又 flaky;notebook 式评测无法规模化。

## 3. 目标用户

- **核心用户(本地开源版)**:正在做 AI 应用 / Agent 的开发者、AI 工程师、AI 创业团队(中国起步,英文社区同步)。
- **付费买家(云端团队版)**:**AI 原生的初创公司 / 小团队**——有预算、ROI 驱动、愿意为"少踩坑、上线快、协作可见"付费。
- **传播节点(冷启动关键)**:作者能直接触达的**科技 / AI / 开发者圈大牛**——既是首批用户,又是口碑喇叭。

## 4. 竞品地图与楔子

| 工具 | 定位 | 短板 / 空位 |
|---|---|---|
| DeepEval | Python/pytest 评测框架,50+ 指标 | 没有 UI、不能协作、非工程师用不了 |
| Promptfoo | YAML、红队、免费 | 2026-03 被 OpenAI 收购,中立性存疑 |
| Langfuse | 可观测性优先 | 评测能力次要、偏浅 |
| Braintrust | 最全的一体化平台 | 偏企业、重,个人/小团队门槛高 |

**四个楔子(为什么能领先):**
1. **中立 catalyst**:打"不绑定任何模型厂、对国产模型友好的 Promptfoo 替代品",时机与叙事现成。
2. **本土空位**:国产模型/平台一等公民 + 中文文档社区,目前无领头羊。
3. **合二为一 + 降门槛**:把"CI 框架 + 带 UI 的平台"做进一个自助、不重的工具,补上 DeepEval"没 UI、非工程师用不了"的空位。
4. **反 vibes 的核心体验**:把"这版变好还是变坏"做成**一眼可见、一键可比**——这是产品的灵魂,而非又一个指标库。

## 5. 产品概览与 MVP 范围

### 5.1 v0.1 开源本地版(YAGNI,一个人 4–6 周目标)——只做 4 件事

> **v0.1 评测对象范围(已确认)**:先做**单轮 prompt + RAG** 评测;模型接入层 / 打分器 / 数据模型按"Agent 可扩展"设计,但**多步 Agent 评测放 Phase 2**,首版不实现。

1. **定义测试集(Dataset)**:一组输入 +(可选)期望/评判标准;支持从生产日志/JSON/CSV 导入(缓解 drift)。
2. **跑评测(Run)**:对某个 prompt / 模型 / Agent 版本跑测试集;打分器 = 规则断言(精确/包含/正则/JSON schema)+ LLM-as-judge + 几个内置指标(相关性 / 忠实度 / 幻觉)。**国产 + 海外模型统一接入。**
3. **杀手锏——版本对比 / 回归视图(Diff)**:两次 Run 做 diff,清楚标出**哪些用例变好、哪些变坏、哪些持平**,回归一眼揪出。
4. **干净的本地 Web UI**:`pip install` / 一条命令起一个本地服务,在浏览器里看结果、读 trace、做人工标注。

### 5.2 MVP 明确不做(留给 Phase 2 云端付费版)

托管仪表盘、团队协作与权限、共享数据集、生产 trace 自动导入、judge↔人工校准、CI 网关托管服务、长期历史回归追踪、红队/安全测试。

> 形成干净的 **开源引流 → 云端团队版收费** 的 open-core 结构。

## 6. 架构与组件(强调边界清晰、可独立测试)

```
┌─────────────────────────────────────────────┐
│  CLI / SDK        (用户入口:定义+跑+对比)      │
├─────────────────────────────────────────────┤
│  Eval Engine      (编排:取数据→调模型→打分)   │
│   ├─ Dataset Loader   (本地文件/日志导入)      │
│   ├─ Provider Layer   (统一模型接入,国产+海外) │
│   ├─ Scorers          (规则断言 / LLM-judge /  │
│   │                     内置指标,可插拔)        │
│   └─ Run Store        (运行结果持久化,本地)    │
├─────────────────────────────────────────────┤
│  Diff Service     (两次 Run 对比 → 回归结论)   │
├─────────────────────────────────────────────┤
│  Local Web UI     (查看/标注/对比,只读引擎)    │
└─────────────────────────────────────────────┘
```

**各组件契约(一句话说清各自做什么、怎么用、依赖谁):**
- **Provider Layer**:输入"模型名 + 请求",输出"标准化响应 + 用量/耗时";内部屏蔽各家差异(DeepSeek/Qwen/豆包/GLM/MiniMax/OpenAI/Claude/Gemini)。其它组件只认这层接口。
- **Scorers**:输入"用例 + 模型输出 +(可选)期望",输出"分数 + 解释";规则类与 LLM-judge 类统一接口、可插拔。
- **Run Store**:本地持久化(默认 SQLite + 文件),供 Diff 与 UI 只读消费。
- **Diff Service**:输入两个 Run id,输出逐用例的"变好/变坏/持平"与汇总。纯函数式、易测。
- **Local Web UI**:只读消费 Run Store / Diff,不反向写引擎,边界清晰。

## 7. 技术栈(实现语言:**Python 优先 — 已确认**)

**Python 优先**(理由:AI 工程受众与 judge/指标生态都在 Python;可复用 LiteLLM 做统一模型接入,天然覆盖国产模型;pytest 式集成已被 DeepEval 验证)。
- 核心引擎 + CLI + SDK:Python
- 本地 UI:FastAPI 提供接口 + 轻量前端(初期可服务端渲染或小型 React/Svelte SPA)
- 本地存储:SQLite + 本地文件
- 模型接入:LiteLLM 风格的 provider 抽象层
- 云端(Phase 2):同一引擎 + 托管应用(Next.js 前端 / FastAPI 后端)+ Postgres(Supabase 起步)+ 对象存储;国内部署走阿里云/腾讯云 + ICP 备案

**备选(未采用):TypeScript 优先**——若日后目标更偏 Web/全栈开发者(`npx` 零安装体验更佳,UI 与核心同语言),可再评估。

## 8. 非功能性要求

- **本地优先 / 隐私**:开源版数据默认全在本地,不外传——对企业很重要的卖点。
- **便宜的 CI**:支持仅在变更用例上跑 judge、缓存判定、限定并发,避免"每个 PR 都超时变贵"。
- **双语 i18n**:文案与文档中英双语;面向中国与全球同一套产品。
- **低成本**:本地版边际成本≈0;云端起步基建 $30–100/月。

## 9. 冷启动与增长(大牛驱动)

1. **先访谈再动手**:动手大建之前,先和 5–10 位 AI/开发者大牛及 AI 团队聊,验证"回归/vibes"痛点与试用意愿。
2. **3–5 位设计伙伴(design partners)**:让大牛拿**真实 Agent 项目**当首批测试集,产出口碑与背书。
3. **公开建造(build in public)** + 现成叙事:"Promptfoo 被 OpenAI 收了——这是那个中立、对国产模型友好的替代品"。
4. **渠道**:国内——掘金 / V2EX / 知乎 / 即刻 / 微信公众号;全球——GitHub / Hacker News / Reddit(r/LocalLLaMA)/ X。
5. **内容钩子**:"别再凭感觉开发(stop vibes-based shipping)"系列教育内容。

## 10. 变现(open-core)

- **开源本地版**:MIT,永久免费——负责获客与口碑。
- **云端 / 团队版**:免费额度 + 按席位或用量(eval 运行数/spans)收费,起步约 ¥团队版 / $20–40/人/月;面向 AI 原生团队。
- **企业自托管**:Phase 3,数据驻留 + 私有部署 + SSO/审计。
- **国内适配**:支持微信/支付宝、年费、对公;海外用 Stripe。

## 11. 风险与应对

| 风险 | 应对 |
|---|---|
| 赛道拥挤、强开源 | 靠锋利楔子(中立 + 本土 + 回归 diff 体验 + 非工程师可用)+ 大牛分发突围 |
| 开发者白嫖、不付费 | open-core,把钱压在团队协作/托管/历史追踪;卖给有预算的 AI 原生团队;全球化抬高天花板 |
| 模型厂/平台自带评测,把你做掉 | 坚持中立 + 多模型,这正是你存在的理由;深耕国产生态护城河 |
| 一个人精力有限 | 残酷收敛 MVP;开源吸引贡献者;Phase 2 才上重功能 |
| 国内开发者工具变现弱 | 双语全球化 + 主攻 AI 原生付费团队;本地版只为获客不指望变现 |

## 12. 验证计划(里程碑)

- **M0(1–2 周)**:访谈 5–10 位目标用户,确认痛点与试用意愿;锁定实现语言。
- **M1(4–6 周)**:开源 v0.1(4 个核心功能)上线 GitHub;3 位设计伙伴在真实项目上用起来。
- **M2**:衡量留存与自发传播(他们是否持续用、是否主动转发);据此决定是否投入云端版。
- **M3**:云端团队版灰度,验证付费。
